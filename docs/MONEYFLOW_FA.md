تاریخ: ۳۱ شهریور ۱۴۰۵ · مبنا: **اندازه‌گیری روی رانرِ GitHub Actions** و روی داده‌ی واقعیِ

## ۱) یافته‌ی اصلی: «جریان پول» عملاً هیچ‌وقت منتشر نمی‌شد

این یک حدس نیست؛ از خودِ فایلِ داده خوانده شد. وضعیت در شروعِ این بازبینی:

```json
"market": {
  "index": { "p": 7280289, "ts": 1789984445000, "day": "2026-09-21", "src": "TGJU" },
  "bt":    { "ts": 1789883106661, "fresh": false, ... }   // ← ۲۸ ساعت قبل
}
```

دو چیز در این فایل غایب بود: **`market.flow` اصلاً وجود نداشت** و مکملِ `bt`
متعلق به جلسه‌یِ روزِ قبل بود. پیامدش در صفحه این بود:

- کارتِ بورس همیشه می‌گفت «جریانِ پول در دسترس نیست»؛
- عاملِ نهمِ حکم («چرخشِ پولِ بورس») که از نسل ۷ در کد هست، **هیچ‌وقت امتیازی نمی‌داد**؛
- رادارِ سلامت، بُعدِ «جریان خرد» را همیشه روی ۵۰ (خنثی) نشان می‌داد.

### چرا؟ دو علتِ زنجیره‌ای

| # | علت | توضیح |
|---|---|---|
| ۱ | **ناشر فقط در ساعتِ بازار می‌خواند** | `tseSessionOpen()` درست است، اما cron گیت‌هاب بهترین‌تلاشی است؛ در روزِ بررسی، هیچ اجرایی در بازه‌یِ ۰۵:۳۰–۰۹:۰۰ UTC (= جلسه‌ی تهران) رخ نداد، پس کلِ جلسه از دست رفت. |
| ۲ | **بعد از بسته‌شدن، جریان دور ریخته می‌شد** | جریانِ پول یک عددِ **روزانه** است، نه لحظه‌ای. کد قدیم فقط وقتی منتشرش می‌کرد که `btFresh` (همان لحظه خوانده شده) باشد؛ یعنی از ۱۲:۳۰ به بعد، عددی را که صبح اندازه‌گیری کرده بود **`delete` می‌کرد**. |

علتِ دوم از اولی هم بدتر است: حتی در روزی که جلسه خوب پوشش داده می‌شد، از عصر به بعد
دیگر اثری از جریانِ پول نبود — با آن‌که واقعاً اندازه‌گیری شده بود.

## ۲) اندازه‌گیریِ منابع (نه حدس)

### ۲٫۱) بورس‌تریدر — منبعِ فعلی، زنده و کامل

پروب روی صفحه‌ی زنده (خروجیِ کامل در `reports/probe-moneyflow.md`) نشان داد پارسر درست
کار می‌کند و حتی چیزهایی هست که تا حالا نمی‌خواندیم:

| داده | مقدارِ نمونه | وضعیتِ قبلی | الان |
|---|---|---|---|
| `ورود پول حقیقی` (ستونِ خرد) | `692.6B` تومان | خوانده می‌شد ولی بعد از بسته‌شدن حذف می‌شد | ✅ **حفظِ جلسه** |
| `ارزش صف خرید` / `ارزش صف فروش` | `5.1T` / `2.1T` تومان | ❌ نمی‌خواندیم | ✅ **جدید: «پولِ پشتِ صف»** |
| `سرانه خرید/فروش حقیقی`، پهنا، صندوق‌ها | `98.2` / `119.8` | ✅ | ✅ |
| سری‌های درون‌جلسه‌ای (`input_money` در `<script>`) | ۲۱۰ نقطه در جلسه | ❌ | ✅ **منحنیِ پیوسته‌یِ روندِ پول** (نمونه‌برداری تا ۴۸ نقطه) |
| منحنیِ تعدادِ صف‌ها (`buysellqty`) | ۲۱۰ نقطه | ❌ | ✅ نمونه‌برداری تا ۴۰ نقطه |

### ۲٫۲) تابلوخوانی — مسدودسازیِ جغرافیایی (یافته‌ی مهم)

`tablokhani.com` از رانرِ گیت‌هاب (US، Microsoft Azure) **پاسخِ HTTP نمی‌دهد**،
اما به شکلِ آموزنده‌ای شکست می‌خورد:

```
* Host tablokhani.com:443 was resolved.        ← DNS کار می‌کند
* Trying 185.208.173.17:443...
* Connected to tablokhani.com port 443         ← TCP برقرار است
* TLSv1.3 (IN), TLS handshake, Finished (20)   ← TLS کامل است
* TLSv1.3 (OUT), TLS change cipher ...
                                               ← و بعد: هیچ. نه 200، نه 403، نه timeoutِ صریح
```

این همان امضایِ **مسدودسازیِ جغرافیایی** است (سرور بعد از دست‌دادن، درخواستِ غیرِایرانی
را بی‌پاسخ رها می‌کند). نتیجه: **ناشرِ سمت‌سرور هرگز نمی‌تواند این سایت را بخواند**،
و برخلافِ TGJU، پراکسی‌های عمومیِ پروژه هم کمکی نمی‌کنند چون آن‌ها هم خارجی‌اند.

پس تابلوخوانی فقط یک راه دارد: **مرورگرِ کاربرِ داخلِ ایران** — دقیقاً همان وضعیتِ TSETMC.

## ۳) چه ساخته شد

| # | تغییر | اثرِ مستقیم |
|---|---|---|
| ۱ | **حفظِ جلسه** (`pickMarketFlow`) | جریانِ پولی که صبح اندازه‌گیری شده، تا پایانِ همان روز منتشر می‌ماند؛ عاملِ نهمِ حکم بالاخره امتیاز می‌دهد. شرطِ صداقت: فقط همان جلسه. |
| ۲ | **سریِ درون‌جلسه‌ای** (`market.flowSeries`) | هر انتشار یک نقطه؛ نمودارِ «روندِ پول در جلسه» با شیب (همت/ساعت)، شتاب و برگشت. |
| ۲٫۵ | **منحنیِ پیوسته‌یِ جلسه** (`market.bt.flowCurve`) | نمودارِ خودِ تابلو (۲۱۰ نقطه، نمونه‌برداری تا ۴۸) مستقیماً استخراج می‌شود؛ ترجیح بر نقاطِ انتشار دارد چون وضوحش بسیار بیشتر است. |
| ۳ | **پولِ پشتِ صف** (`market.bt.queue`) | ارزشِ ریالیِ صف‌های خرید/فروش (تعدادِ صف نمی‌گفت چقدر پول پشتش است). |
| ۴ | **تاریخچه‌ی جلسه‌ای** (`history.daily.TSEFLOW`) | «۳ جلسه‌ی پیاپی خروج» — رفتار در برابر اتفاق. |
| ۵ | **تابلوخوانی در مرورگر** (`parseTablokhani`) | برای کاربرِ داخلِ ایران: شاخص‌ها + ارزشِ صف‌ها + سریِ محلیِ جلسه + پیوندِ عمیق به نمادها. |
| ۶ | **سه عاملِ تازه در حکم** (۱۰: شیبِ جلسه، ۱۱: پولِ پشتِ صف، ۱۲: پیاپی‌بودن) | حکم از «عددِ لحظه‌ای» به «جهتِ حرکت» ارتقا یافت. |
| ۷ | **رفعِ باگِ «این هفته»** | سطرِ زمینه‌ی هفتگی همیشه آخرین سطر ساخته می‌شد و با آمدنِ هر عاملِ تازه از انتهای فهرست بیرون می‌افتاد؛ حالا جای تضمینی دارد. |

## ۴) مدلِ داده

**`live.json → market`**

```json
{
  "index":  { "p": 7280289, "high": 7345567, "low": 7279864, "ts": 1789984445000, "day": "2026-09-21", "src": "TGJU" },
  "day": "2026-09-21",
  "flow":   { "netToman": -3.2e12, "ratio": -0.12, "n": 900, "src": "BourseTrader",
              "ts": 1789968000000, "day": "2026-09-21", "fresh": false },
  "flowSeries": [[1789956000000, 1e12], [1789962000000, -1e12], [1789968000000, -3.2e12]],
  "bt": { "...": "شاخص‌ها، صندوق‌ها، پهنا، سرانه",
          "queue": { "buyToman": 5.1e12, "sellToman": 2.1e12, "netToman": 3.0e12, "buyShare": 0.708 },
          "flowCurve": { "v": [-107, -400, -900, -1400, -1800], "n": 5, "raw": 210,
                         "unit": "milliard_toman", "first": -107, "last": -1800, "min": -1800, "max": -107 },
          "queueCurve": { "buy": [128, 160, 190, 210, 225], "sell": [129, 140, 160, 170, 174], "n": 5 } }
}
```

- `flow.fresh=false` یعنی «اندازه‌گیریِ امروز، اما نه همین لحظه» (بازار بسته است).
- `flowSeries` فقط نقاطِ همان روزِ تهران را نگه می‌دارد (جلسه‌ی جدید = سریِ جدید).

**`history.json → daily.TSEFLOW`**

```json
"TSEFLOW": [["2026-09-20", -2000000000000], ["2026-09-21", -3200000000000]]
```

چرا جدا از `addPoint`؟ چون مقدارش می‌تواند **منفی** باشد (خروجِ پول) و `addPoint` برای
قیمت ساخته شده و فقط مثبت می‌پذیرد. به‌روزرسانی درجا: آخرین مقدارِ جلسه همان عددِ نهایی است.

## ۵) نگهبان‌ها (فلسفه‌ی همیشگی: سکوت به‌جای عددِ غلط)

| بخش | نگهبان |
|---|---|
| `pickMarketFlow` | اگر جریان متعلق به جلسه‌یِ شاخص نباشد → **منتشر نمی‌شود**؛ بدون منبع → سکوت؛ هرگز از روی شاخص ساخته نمی‌شود. |
| `flowSeries` | فقط اعدادِ متناهی، فقط رو‌به‌جلو در زمان، فقط همان جلسه، حداکثر ۲۴ نقطه، ادغامِ فاصله‌هایِ زیرِ ۵ دقیقه. |
| `flowCurve` | فقط اعدادِ متناهی، ۵ تا ۲۰۰ نقطه، هیچ نقطه‌ای بزرگ‌تر از ۵۰۰۰ همت؛ و **تطبیق با عددِ جدول** (نسبتِ ۰٫۴ تا ۲٫۵) — در غیر این صورت کلِ منحنی کنار گذاشته می‌شود. |
| `queue` | ارزش نمی‌تواند منفی یا بزرگ‌تر از کلِ ارزشِ بازار باشد؛ `buyShare` باید در [۰٬۱] باشد وگرنه دوباره از مبالغ حساب می‌شود. |
| `parseTablokhani` | هر بخش مستقل نگهبانی می‌شود؛ شاخصِ خارج از بازه رد می‌شود؛ واحدِ ارزشِ صف‌ها از **عنوانِ خودِ جدول** («میلیارد تومان») گرفته می‌شود نه از حدس روی عدد؛ ارقامِ فارسی و «٪» عربی و فلشِ ▼/▲ برای جهتِ درصد، همگی تبدیل می‌شوند. |
| کلاینت | `btShape` هر بخش را باز اعتبارسنجی می‌کند؛ یک بخشِ خراب بقیه را حذف نمی‌کند و اگر هیچ بخشِ معتبری نماند کلِ مکمل نگه داشته نمی‌شود. |

## ۶) عامل‌هایِ بورس در «حکم امروز»

سقفِ اثرِ کلِ بورس همان **۲٫۵±** ماند (بورس تأییدکننده است، نه پیشران)؛ عامل‌هایِ تازه
با وزنِ کم اضافه شدند تا تصویر دقیق‌تر شود بدون اینکه بورس بر حکم مسلط شود.

| عامل | شرط | امتیاز |
|---|---|---|
| جریانِ خرد (۹) | `|نسبت| ≥ ۰٫۱۰` یا (≥۰٫۰۴ و هم‌جهت با شاخص) | ±۱ |
| پهنا، درآمد ثابت، سهامی، سرانه، صفِ خرید | همان آستانه‌های نسل ۸ | ±۰٫۴ تا ±۱ |
| **۱۰) شیبِ جلسه** | `|شیب| ≥ ۰٫۵ همت در ساعت` | ±۰٫۵ / ∓۰٫۴ |
| **۱۱) پولِ پشتِ صف** | سهمِ صفِ خرید ≥ ۷۰٪ یا ≤ ۳۰٪ | ±۰٫۵ |
| **۱۲) پیاپی‌بودن** | همه‌ی جلسه‌های موجود هم‌جهت (حداقل ۲ جلسه) | ±۰٫۴ / ∓۰٫۳ |

## ۷) آنچه هنوز باز است (و چرا عمداً نیمه‌کاره گذاشته شد)

1. ~~سری‌های درون‌جلسه‌ایِ بورس‌تریدر استخراج نشد.~~ → **انجام شد.** نمودارِ
   `input_money` (ورود/خروجِ پولِ حقیقیِ خرد، ۲۱۰ نقطه) و `buysellqty` (تعدادِ صف‌ها)
   استخراج می‌شوند؛ با این احتیاط‌ها:
   - منحنی **محورِ زمان ندارد** (فقط ترتیب)، پس هیچ timestampای برای نقاط ساخته
     نمی‌شود و نمودار هم ادعا نمی‌کند هر نقطه چه ساعتی بوده؛
   - یک **نگهبانِ تطبیق** آخرین نقطه را با خالصِ جدول می‌سنجد؛ اگر نسبت از
     بازه‌یِ ۰٫۴ تا ۲٫۵ بیرون بزند یعنی نمودار چیزِ دیگری است و منحنی منتشر نمی‌شود؛
   - نقاطِ زمان‌دارِ انتشارهای خودمان (`flowSeries`) همچنان مبنایِ **شیبِ همت/ساعت**‌اند،
     چون آن‌ها زمانِ واقعی دارند.
2. **CORSِ تابلوخوانی هنوز اندازه‌گیری نشده.** نمی‌توان از بیرونِ ایران سنجید. راهِ سنجش:
   `probe.html` را از داخل ایران باز کن (تبلوخانی به فهرست اضافه شده) و گزارش را بفرست.
   - اگر جواب گرفت → پارسرِ آماده، همان لحظه فعال می‌شود؛
   - اگر CORS نداد → تابلوخوانی برایِ ما فقط «پیوندِ عمیق» می‌ماند (که الان هم هست).
3. **فازِ ۲٫۵ (TSETMC از مرورگرِ ایران)** همچنان باز است و با همان `probe.html` اندازه می‌شود.

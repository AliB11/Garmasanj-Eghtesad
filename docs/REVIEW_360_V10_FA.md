# بازبینی ۳۶۰ درجه‌ی نسل ۱۰ — بورس آنی و سبد بورسی

تاریخ بازبینی: ۱۴۰۵/۰۷/۱۳ (۵ اکتبر ۲۰۲۶)

## دامنه‌ی بررسی

بازبینی لایه‌به‌لایه روی پوسته‌ی HTML/CSS، موتور داده، زمان‌بند مرورگر، پارسرهای منابع، مدل بورس، نمودارها، ترکیب‌ساز، ناشر Node، تاریخچه، Service Worker، Workflowهای GitHub Actions و تست‌ها انجام شد.

کنترل‌های اجراشده:

- بررسی نحوی تمام فایل‌های JavaScript مرورگر، Service Worker، ناشر و تاریخچه؛
- اجرای کامل ۷ سوئیت رگرسیون (`tests/run.sh`)؛
- اعتبارسنجی HTML هر سه صفحه با `html-validate`؛
- بررسی شناسه‌های تکراری، مسیر فایل‌های محلی و پاسخ HTTP پیش‌نمایش؛
- بوت آفلاین، شبکه‌ی ماک‌شده، تاریخچه، مقایسه، بورس، جریان پول و تعامل‌های صفحه در jsdom؛
- تست مستقیم مدل جدید TGJU بورس، حفظ مکمل سرور و وزن بورس در پرتفوی.

## منطق سهم بورس

وزن پایه‌ی بورس به‌صورت محدود از این سه ورودی می‌آید:

- تحمل ریسک بیشتر → سهم بورس بیشتر؛
- افق بلندتر → سهم بورس بیشتر؛
- نیاز فوری به نقدینگی → سهم بورس کمتر.

بعد، فقط در صورت داشتن حداقل دو مؤلفه‌ی معتبر و داده‌ی غیرکهنه، نبض بورس وزن را حداکثر چند واحد درصد می‌چرخاند. این محدودیت مانع می‌شود یک عدد پرت یا یک منبع ناقص کل سبد را تغییر دهد. مجموع وزن‌ها پس از هر تغییر دوباره دقیقاً به ۱۰۰٪ نرمال می‌شود.

## نتیجه‌ی آزمون

- همه‌ی تست‌های پروژه سبز؛
- سوئیت بورس: ۵۵ تست، صفر شکست؛
- خطای پنجره در سناریوهای jsdom: صفر؛
- HTML: بدون خطای اعتبارسنجی؛
- `git diff --check`: بدون خطای whitespace؛
- پیش‌نمایش HTTP: صفحه، داده‌ی زنده، دکمه‌ی بورس و سهم بورس با پاسخ ۲۰۰ در دسترس‌اند.

## محدودیت صادقانه

«آنی» یعنی همان لحظه تمام مسیرهای قابل‌دسترسی از شبکه‌ی کاربر استعلام می‌شوند؛ تضمین نمی‌کند منبع بیرونی عدد تازه‌تری تولید کرده باشد. اگر بازار بسته یا منبع منطقه‌ای خارج از دسترس باشد، آخرین داده‌ی معتبر حفظ و با سن واقعی نمایش داده می‌شود؛ سامانه برای تازه به‌نظر رسیدن، timestamp یا جریان پول نمی‌سازد.
